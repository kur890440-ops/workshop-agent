# ACTIVE_DIALOG_BUTTONS

## L0 — архитектура

Управление формой выполняется локально до интерпретации значения поля и вызова LLM. Общий слой Telegram UI добавляет навигацию под последним сообщением формы, включая ошибки. Кнопки находятся под сообщением, а не закреплены у края экрана.

Временная форма, короткая сессия и рабочая задача — разные сущности. Выход из ввода не переводит FSM, не отменяет рабочую задачу, не удаляет память и не откатывает сохранённые операции.

## L1 — состояние

`formNavigation` принадлежит экземпляру `setupSession`: версия отображённого шага, текущий снимок полей, история предыдущих шагов и message_id последней клавиатуры. Снимки содержат копии полей и списков ID. При возврате к выбору материала список читается заново.

`buttonAction` связан с пользователем, чатом, Workshop, экземпляром формы и версией шага. Общие nonce и TTL продолжают действовать. После перехода предыдущие кнопки удаляются из серверного реестра; Telegram-клавиатура снимается через editMessageReplyMarkup, когда известен message_id. Ошибка удаления клавиатуры не возвращает старым кнопкам права исполнения.

Для черновика сборки используются существующие ID и revision, для ввода выпуска — Task/Session/Expires. Создание мастерской сохраняет существующий uiState. Адаптеры общего слоя не создают новые задачи и не подменяют владельцев состояния. Миграция SQLite не требуется.

## L2 — решения

- WA-D109: активная форма показывает «Отмена», «Главное меню» и «Назад», когда есть предыдущий шаг. Ошибка ввода также получает клавиатуру.
- WA-D110: /setup_stop и точные фразы «отмена», «отмени», «остановись», «прекрати ввод», «выйти из ввода» отменяют форму. Регистр и пробелы по краям не учитываются. Вне активного ввода этот слой не интерпретирует их как отмену задачи.
- WA-D111: /start, /menu, «главное меню», /workshop открывают главное меню с выходом из формы; /workshops открывает выбор мастерской. Команды обрабатываются раньше числового поля.
- WA-D112: попытка управлять задачей из формы предлагает продолжить ввод либо отменить его и открыть задачу. Завершение не выполняется автоматически. Day14 validation и подтверждение выпуска остаются обязательными.
- WA-D113: отмена редактора состава полностью закрывает форму и возвращает список товаров. Это заменяет прежнюю локальную семантику /setup_stop, возвращавшую в редактор состава. Подтверждённые ранее изменения остаются сохранёнными.
- WA-D114: после сохранения редактор не возвращает пользователя к устаревшей форме подтверждения через историю «Назад». Права и доменные версии проверяются прежними сервисами при сохранении.

## L3 — пользовательские сценарии

Материалы, создание товара, редактирование товара, состав товара и выбор рабочей единицы используют общую навигацию. Черновик сборки, ввод фактического выпуска и создание мастерской подключены адаптерами к своим существующим обработчикам.

Пример: Гипс 10 кг → редактировать → -50 → «Нельзя списать 50 кг: доступно 10 кг. Введите другое значение.» с кнопками. «Назад» возвращает свежий список выбора, «Отмена» — меню материалов, «Главное меню» — меню мастерской. Изменений склада при ошибке нет.

Все несохранённые значения отбрасываются при выходе; бот сообщает об этом. После перезапуска in-memory формы не восстанавливаются, старые callback обрабатываются как устаревшие.

Проверки: тестовый Telegram-транспорт, кнопки после ошибок, повторный ввод после возврата, отсутствие сохранения при отмене, навигационные команды, конфликт с управлением задачей, stale-step и stale-workshop callback, сохранность задачи, регрессия состава/товаров/материалов/завершения. Реальные сообщения в рабочий Telegram-чат не отправляются.

Проверка: `go test ./...`; сборка: `go build -o bin\workshop-agent.exe ./cmd/workshop-agent`.

Требуется перезапуск бота: `Ctrl+C` → `.\bin\workshop-agent.exe`.

Проверено 2026-09-18: `go test ./...` — PASS; сборка `bin/workshop-agent.exe` — PASS. Включены проверки отказа Telegram при снятии старой клавиатуры и чужого callback: оба случая не восстанавливают права старой кнопки и не отменяют чужую форму.
