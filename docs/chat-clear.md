# CHAT_CLEAR — L0–L3

@PROJECT:WORKSHOP_AGENT
@L3:CHAT_CLEAR
@NO_COMPRESS

## L0 — архитектура

Очистка — локальная команда Telegram Interface, без LLM. Identity определяет
внутреннего User, а chat_id проверяется против его Telegram ID. Workshop и её
роль для очистки собственного личного чата не требуются. Доменные данные не удаляются.

## L1 — сценарий и данные

Точные команды: `/clear`, «очисти», «очистить», «очисти чат», «очистить чат»,
«очисти диалог», «очистить диалог», «удали переписку», «удалить переписку».
Регистр и пробелы по краям игнорируются. Произвольные фразы вроде «очисти склад»
не являются командой. Команда доступна и во время незавершённой формы.

Бот спрашивает: «Удалить доступные сообщения из этого чата? Данные мастерской,
задачи и сохранённые настройки останутся. Telegram может ограничивать удаление
старых сообщений». Кнопки — «Очистить чат» и «Отмена».

Подтверждение одноразовое, связано с пользователем и чатом, действует 15 минут.
Новый запрос очистки отменяет прежние кнопки подтверждения. «Отмена» не удаляет
сообщения и не закрывает контекст. Подтверждение закрывает активные краткосрочные
сессии этого пользователя в этом чате для всех Workshops, сбрасывает формы,
UI-состояние, старые кнопки и неподтверждённые действия текущего чата.
Рабочая задача, пользовательские предпочтения, долгосрочная память и Audit Log
сохраняются. Архивные записи краткосрочных сессий не стираются, но не используются
как активный контекст нового диалога.

Миграция 103 добавляет:

- `telegram_messages`: chat_id, user_id, message_id, дата отправки и признак dice.
- `telegram_clear_limits`: время допустимой повторной попытки после rate limit.

Тексты в реестр удаления не записываются. Регистрируются входящие сообщения,
включая обновления без текста, результаты отправки ответов и меню, а также
сообщения, на которых получен callback. Реестр сохраняется между перезапусками.
Миграция использует существующее резервное копирование SQLite.

## L2 — решения

### WA-D038 — удаление только известных сообщений

Используются реальные ID из обновлений и ответов Telegram. ID не перебираются
и не вычисляются. История до появления учёта полностью недоступна: Bot API
не предоставляет обычному боту метод чтения всей прошлой переписки.
Операция работает только в личном чате владельца соответствующего Telegram ID.

### WA-D039 — ограничения Telegram и достоверный результат

Документация проверена 2026-09-17:
[deleteMessage](https://core.telegram.org/bots/api#deletemessage),
[deleteMessages](https://core.telegram.org/bots/api#deletemessages),
[Getting updates](https://core.telegram.org/bots/api#getting-updates).

Обычный бот может удалять собственные и входящие сообщения личного чата младше
48 часов. Для dice в личном чате необходимо также, чтобы прошло более 24 часов.
Некоторые служебные сообщения недоступны для удаления. Обновления Telegram
не являются архивом переписки; невыданные обновления сохраняются не более 24 часов.

Пакетный метод принимает 1–100 ID, пропускает отсутствующие сообщения и не возвращает
поштучного результата. Поэтому реализация использует `deleteMessage`, чтобы
различать подтверждённое удаление и уже отсутствовавшие сообщения.

Сообщения старше лимита, слишком свежие dice и записи без достоверной даты
пропускаются. Сервисные ограничения дополнительно обрабатываются по ответу API.
Результат содержит счётчики удалённых, уже отсутствующих, пропущенных, ошибок
и непроверенных сообщений. Полная очистка всей истории не обещается. Итоговое
сообщение остаётся в чате и учитывается для следующей очистки.

### WA-D040 — частичные ошибки и повторная попытка

Локальная запись удаляется только после подтверждения удаления или ответа,
что сообщение уже отсутствует. Ошибки и пропуски сохраняют запись.
Отказ конкретному сообщению с кодом 400 позволяет продолжить обработку остальных.
Сетевая ошибка, серверная ошибка или отказ доступа останавливают текущий проход.
При 429 сохраняется retry_after; новые попытки раньше срока не вызывают удаление.
Автоматического ожидания или бесконечного повтора нет: пользователь повторяет `/clear`.
Текст ответа API и URL с токеном не выводятся в диагностике ошибок.

Очистка Telegram и SQLite не являются общей транзакцией. Если сообщение удалено,
а локальный учёт обновить не удалось, запись остаётся для проверки следующей
попыткой. Если ответ Telegram потерян в сети, удаление не считается подтверждённым.
Закрытие краткосрочного контекста сохраняется и при частичном отказе Telegram.
Если отправка итогового сообщения тоже недоступна, доставку результата гарантировать
невозможно; бот не подменяет ошибку сообщением об успешной очистке.

## L3 — реализация и проверки

Основные файлы: `internal/telegram/clear.go`, общая отправка API в `identity.go`,
учёт входящих сообщений в `bot.go`, миграция `internal/storage/chat_clear.go`.

Тесты `internal/telegram/clear_test.go` используют тестовый HTTP-транспорт:
варианты команды, точное распознавание, отмена, одноразовость, срок действия,
чужой callback, изоляция чатов, входящие и исходящие сообщения, меню, медиа,
dice, старые и неизвестные даты, отсутствующие сообщения, частичные отказы,
сетевая ошибка, 429 и повтор раньше retry_after. Отдельно проверены закрытие
сессии, пустой новый short-term context, сохранность рабочей задачи, материала
и предпочтений, сброс формы и старых кнопок. Реальный чат в тестах не очищается.

После установки требуется перезапуск: **Ctrl+C → `.\bin\workshop-agent.exe`**.
Учёт новых сообщений начинается с запуска обновлённой версии.
