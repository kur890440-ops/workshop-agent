# ASSEMBLY_TASK_INTENT

Обновление: персональная видимость рабочих задач заменена общим списком Workshop
и назначением исполнителя в [WORKSHOP_SHARED_TASKS](workshop-shared-tasks.md).
Ниже сохранена история исходного решения; актуальная модель доступа — WA-D086–WA-D092.

@PROJECT:WORKSHOP_AGENT @UPDATE @NO_COMPRESS

## L0 — Architecture

Telegram → Identity / active Workshop → локальная маршрутизация или существующий
семантический интерпретатор → Products / BOM / Working Memory → FSM → SQLite.
Просмотр, подготовка черновика и переход FSM — отдельные действия.
Полноценной сущности заказа нет: бот честно показывает личные задачи сборки,
не создавая параллельную систему заказов и не выдавая задачи за выпуск продукции.

## L1 — Entities and scope

- Список использует working_memory: assembly и production со статусами
  active, waiting_input (совместимость), paused. Терминальные записи исключены.
- Задачи выбираются по user_id + workshop_id. Общая Workshop не раскрывает чужие
  задачи. Membership, права, активная Workshop и версия проверяются при действиях.
- Пагинация по восемь задач/товаров. Кнопки связаны с task_id/product_id;
  номер служит позицией отображения. Ввод номера товара использует снимок каталога.
- Черновик хранится в существующей pending_actions с user/chat/workshop/session
  scope, сроком действия и revision. Старое подтверждение не применяет новые данные.
- Подтверждение атомарно потребляет черновик, создаёт FSM-задачу, историю перехода
  и Audit Log. Проверяются актуальные права, товар, сессия, revision и отсутствие
  другой активной задачи. Ошибка откатывает всю операцию.

## L2 — Decisions

- **WA-D079:** `/orders`, «заказ», «заказы», «текущие заказы», «покажи заказы»,
  «список заказов», «собрать заказ» открывают текущие задачи. Это заменяет правило,
  направлявшее любое слово «заказ» в создание. Упоминание номера заказа предлагает
  выбор существующей задачи, не трактует этот номер как product_id.
- **WA-D080:** «новый заказ», «создать заказ», «новая задача сборки» открывают
  черновик задачи сборки. UI не утверждает, что создан настоящий заказ.
- **WA-D081:** «собрать 5 дефлекторов», «сделаем 5 сливов», «нужно собрать 3 набора»
  предлагают подходящие товары текущей Workshop. Количество сохраняется.
  Единственный кандидат тоже требует выбора; неоднозначный не выбирается случайно.
  Прежние сценарии «соберём …» сохраняют подтверждение параметров задачи.
- **WA-D082:** подтверждение создаёт planning / confirm_task / FSM v1, не execution.
  Товар и количество повторно не запрашиваются. При отсутствии BOM бот сообщает,
  что потребность и дефицит рассчитать нельзя.
- **WA-D083:** выбранная существующая задача сохраняет task_id. Явная подготовка
  legacy-задачи переводит её в FSM v1 без дубликата; просмотр формат не меняет.
- **WA-D084:** действия карточки требуют подтверждения и проверки версии FSM.
  При другой активной задаче предлагается открыть её либо явно поставить на паузу.
  Автоматического переключения нет; несколько paused-задач выбираются явно.
- **WA-D085:** чтение, создание задачи и переходы текущего FSM не меняют склад,
  BOM и production_records. Фактический выпуск остаётся отдельной возможностью.

## L3 — UI and checks

«заказы» → список с заголовком «Учёт заказов пока не настроен» → выбор → карточка →
допустимое действие → подтверждение. Пустой список: «Текущих задач сборки нет».
Кнопка «Новая задача сборки» доступна при TasksCreate.

«Собрать 5 дефлекторов» → кандидаты → «Выбрать» → параметры → «Создать задачу» → FSM.
Доступны изменение товара/количества и отмена. «Нет, 10» на подтверждении исправляет
тот же черновик. Количество: целое от 1 до 1 000 000 000. Ноль, отрицательные,
дробные, NaN и Inf отклоняются. Число заказов отдельно от числа изделий:
уточняется количество на заказ, итог проверяется на переполнение.
`/setup_stop` отменяет черновик, сохраняя существующую рабочую задачу.
После рестарта нужно открыть новое меню; старые кнопки недействительны.

Тесты используют временные БД и fake Telegram transport: локальные фразы,
семантический вход, пагинация, изоляция, терминальные статусы, legacy adoption,
пауза/продолжение, корректировка количества, повторное и устаревшее подтверждение,
отмена, смена Workshop, отзыв прав, откат транзакции и сохранность склада.
Общие FSM-тесты проверяют новую сессию и перезапуск.

Проверка: `go test ./...`.
Сборка: `go build -o bin/workshop-agent.exe ./cmd/workshop-agent`.
Для применения изменений: **Ctrl+C → `.\bin\workshop-agent.exe`**.
