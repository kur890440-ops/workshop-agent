# PRODUCTS_EDIT_MENU

## L0 — границы

Telegram menu → Identity / Active Workshop / Permissions → Products service
→ SQLite transaction → products + product_movements + Audit Log.

Редактор работает локально, без LLM. Материалы, BOM и производственные записи
не меняются. Меню чтения доступно с products.read; кнопки добавления и
редактирования — с products.write. На каждом шаге проверяются оба права,
а перед записью — ещё раз внутри транзакции вместе с активной Workshop.

## L1 — состояние и данные

Используются существующие setupSession и одноразовые кнопки Telegram UI.
Форма product_edit хранит снимок product IDs, выбранный product_id,
поле, введённое значение, режим изменения, ожидаемое старое значение,
session ID и срок действия 15 минут. Отдельной системы форм не добавлено.

Этапы: выбор номера → карточка → ввод или выбор типа → подтверждение.
Отображаемый номер связан с ID снимка, а не с текущей сортировкой таблицы.
Кнопки относятся к user + chat + workshop и конкретному экрану предложения.
Переход на другой экран инвалидирует предыдущие кнопки редактора.

Products.Product читает карточку; EditValue валидирует ввод; ApplyEdit
блокирует запись перед чтением, проверяет права, Workshop и ожидаемое
значение поля, затем сохраняет фактическое изменение и аудит атомарно.
Для current_stock добавляется product_movements с фактической delta,
movement_type=manual_adjustment, reference_type=manual и внутренним user_id.
Существующий UpdateProduct также использует эту транзакционную реализацию.

## L2 — решения

- **WA-D050:** редактор открывается из меню товаров. Поля: название, SKU,
  тип, остаток, минимальный остаток. Типы показываются по-русски:
  Готовое изделие / Набор / Полуфабрикат.
- **WA-D051:** остаток без знака — абсолютное значение, с + или - — delta.
  Минимум всегда абсолютный. Дробные значения поддерживаются, поскольку
  существующие модель и сценарий создания используют float64/REAL.
  Принимаются точка и запятая; NaN, бесконечность, экспоненциальная запись,
  некорректные числа, отрицательный итог и нулевые +0/-0 отклоняются.
  Допустимый итог: 0–1 000 000 000 000. Дроби не округляются до целых.
- **WA-D052:** сравнение ожидаемого и актуального значения происходит в
  транзакции. При конфликте ничего не записывается, предложение обновляется
  и требует нового подтверждения. Относительная delta пересчитывается от
  свежего остатка. Неизменившееся значение не создаёт движения или аудита.
- **WA-D053:** SKU — строка, ведущие нули сохраняются; '-' очищает артикул.
  Существующая схема не устанавливает уникальность SKU, новое ограничение
  не вводится. Для вводимых в редакторе названия и SKU принят предел
  200 символов; пустое название запрещено. Старые записи не мигрируются.
- **WA-D054:** открытие редактора и выход из него не удаляют черновик сборки
  и не закрывают активную задачу. Номер в форме относится к редактированию.
  /setup_stop в редакторе и «Назад к товарам» возвращают список с сохранением
  черновика. Смена Workshop, новая сессия и очистка чата сохраняют общие
  правила сброса контекста. Перезапуск процесса теряет несохранённые формы.

## L3 — использование и проверки

Карточка дополнена кнопкой [«Состав товара»](product-composition-menu.md).
Для пользователей без products.write добавлен вход «Просмотреть продукт»;
просмотр карточки требует products.read, изменение её полей — products.write,
а изменение состава проверяет отдельное bom.write. Это расширяет первоначальный
сценарий карточки редактора, не выдавая права записи пользователю просмотра.

```text
товары → Редактировать продукт → 1 → Остаток → +3
Было: 5 шт
Будет: 8 шт
Изменение: +3 шт
[Сохранить] [Отмена]
```

После сохранения бот сообщает результат и показывает обновлённую карточку.
«Отмена» возвращает карточку без записи. /products выходит из формы без
сохранения; обычное слово «Товары» в поле названия остаётся названием.
После создания продукта автоматически возвращается меню продуктов.

Проверки в editing_test.go и product_edit_test.go используют временные БД
и тестовый Telegram-транспорт:

- Все пять полей, ведущие нули, очистка SKU, русские названия типов.
- Абсолютные и относительные остатки, дроби, ноль, ошибки и пределы.
- Отсутствие записи до подтверждения и отсутствие нулевых движений/аудита.
- Конфликт остатка и названия, повторное подтверждение и отмена.
- Откат при ошибке вставки движения или аудита.
- Смена сортировки после показа списка с сохранением product_id.
- Права просмотра, отзыв прав, чужие callback, недоступный product_id.
- /setup_stop, /products, /session new, очистка чата, срок формы,
  смена Workshop туда и обратно, повторное нажатие.
- Сохранность BOM и продолжение черновика сборки до задачи на 15 шт.
- Отсутствие LLM-вызовов в сценариях редактора.

Новая схема БД и миграция не требуются. Удаление продуктов не добавлено.
Дробные остатки сохранены; задача сборки по-прежнему считает целые изделия.

Проверка: go test ./...
Сборка: go build -o bin/workshop-agent.exe ./cmd/workshop-agent

Нужен перезапуск бота: **Ctrl+C → .\bin\workshop-agent.exe**.
