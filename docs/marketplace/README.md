## Правила сохранения контекста

Метки @NO_COMPRESS и @PRESERVE не отключают техническое сжатие истории диалога.
Постоянные требования и решения записываются в файлы и перечитываются после сжатия.
Нельзя рассчитывать, что исходный промпт останется в контексте полностью.

Перед крупными изменениями записать решение в основной слой. По завершении этапа
обновить L3 и WORKSTATE. План, написанный код, пройденные mock-тесты и проверка
реального API имеют разные статусы и доказательства.

После сжатия или возобновления:

1. Прочитать эту карту, L0 и относящиеся к задаче L1/L2.
2. Прочитать текущий этап L3 и WORKSTATE.
3. Сверить записи с кодом, git status и результатами проверок.
4. Продолжить с первого незавершённого действия. Не повторять автоматически
   миграции, внешние запросы или другие уже выполненные операции.

Можно сокращать повторяющиеся обсуждения, промежуточные поиски, разобранные логи
и хронологию без влияния на результат. Для отвергнутого варианта сохранить причину
отказа в решении, если она влияет на выбор архитектуры.

Нельзя терять ограничения, согласованные изменения, нерешённые вопросы,
непройденные проверки, различие mock/live и ссылки на доказательства.
Изменения обязательных решений оформляются новым ID со ссылкой «заменяет»;
исходное решение сохраняется как история. Не сокращать L0 до «соблюдать безопасность».
