# Первый этап WB: настройка и использование

## Day17: остатки через MCP

После запуска обновлённого `bin/workshop-agent.exe` из корня проекта:
`/wb_stocks` — получить остатки через MCP; `/wb_stocks trace` — добавить безопасный
технический trace. Сервер `bin/wb-mcp-server-day16.exe` приложение запускает само.
Нужны включённая привязка мастерской, ранее проверенный seller ID и marketplace.read.
Сервер сам читает корневой `.env`; токен в аргументы инструмента не передаётся.
Сохранённые ограничения WB продолжают действовать, включая seller-info.
Старые `/wb stocks` и кнопка остатков работают через прежний sync/cache flow.
Подробности и границы: [Day17](../day17-first-mcp-tool.md).

Offline-демонстрация без чтения `.env`, реального WB и Telegram:

```powershell
.\bin\workshop-agent-check.exe day17-mcp-report
```

## Исправление rate_limited (2026-09-23)

Основной бинарник: `bin/workshop-agent.exe`; проверочный: `bin/workshop-agent-check.exe`.
Остановите старый бот через Ctrl+C и запустите новый из корня проекта.
При первом запуске применяется migration 111 с резервной копией перед миграцией.
Она добавляет метаданные ожидания; производственные таблицы не изменяет.
Migration 112 затем однократно снимает прежние local_interval и их сроки в
представлении, сохраняя явно помеченные серверные ограничения WB.

WB_API_PROFILE больше не требуется: искусственные интервалы 24ч/30мин отменены
по запросу пользователя (WA-D148). Локальные интервалы — 1 мин для проверки кабинета
и 20 с для остатков; более длинный срок от WB сохраняется и соблюдается.
Настоящий .env разработчиком не менялся. Тип токена по-прежнему не установлен.

Подтверждённая identity переиспользуется в памяти 24 ч при неизменном подключении.
Рестарт требует новой проверки: старый seller_id в SQLite не доказывает, что
новый токен принадлежит тому же кабинету. Серверный cooldown сохраняется отдельно,
перезапуск его не обнуляет; если новая обязательная проверка ещё запрещена,
загрузка ждёт следующего разрешённого действия пользователя, а не обходит проверку.

В /wb теперь видны начало/конец попытки и последний полный успех отдельно.
При ошибке seller-info остатки отмечаются как «запрос не выполнялся».
При известном сроке выводятся UTC-время и источник: заголовки WB либо локальная
оценка. Нового фонового таймера/автоматического повтора после этого срока нет:
нажмите «Остатки WB» снова после указанного времени. /wb читает только SQLite.
429 ещё возможен из-за квоты WB и других приложений того же кабинета.

Границы и безопасность определены [L0](L0-scope.md), хранение — [L1](L1-architecture-data.md),
контракты — [L2](L2-contracts-decisions.md). Текущие ограничения сверки WB:
[API-CONTRACTS](API-CONTRACTS.md). Live-проверка ещё не проводилась.

1. Владелец приложения локально добавляет `WB_API_TOKEN=<свой токен>` в корневой
   `.env`. Шаблон пустой переменной есть в `.env.example`. В Telegram токен не вводить.
   `.env` хранит открытый текст: доступ только учётной записи приложения и владельцу,
   секрет не должен попадать в общие копии и Git. Переменная окружения процесса,
   если уже задана, имеет приоритет над `.env` в существующем godotenv.Load.
2. Перезапустить приложение из корня проекта. Замена токена применяется только
   после перезапуска. При обычном запуске storage выполняет миграцию 110;
   существующая база получает резервную копию перед применением новой миграции.
   Во время разработки рабочая база не открывалась и не мигрировалась.
3. В личном чате выбрать нужную мастерскую, открыть `/wb` или кнопку Wildberries
   в `/workshop`. Владелец нажимает «Подключить WB» и «Подтвердить».
4. Нажать «Проверить WB», затем «Обновить WB». Ответ о запуске приходит сразу;
   прогресс и результаты смотреть через `/wb`. Периодического опроса WB нет.
5. «Остатки WB» или `/wb stocks` автоматически запускает загрузку остатков
   на складах WB и после завершения присылает результат. Во время загрузки бот
   остаётся доступен; повторные нажатия не создают параллельных запросов.
   Остатки складов продавца обновляются отдельно через «Обновить WB».

Чтение/обновление разрешены активным участникам с marketplace.read. Привязка,
отключение и сопоставления — OWNER с marketplace.manage. Настроенный кабинет
закреплён за одной мастерской; переноса между мастерскими в первом этапе нет.
Отключение отменяет загрузку; сохранённые данные остаются доступны с отметкой
отключения. Токен не удаляется. Иной sid после замены токена не смешивается с
предыдущим кабинетом: загрузка блокируется.

| Команда | Действие |
|---|---|
| `/wb`, `/wb status` | настройка, кабинет, результаты и последнее полное обновление по типам |
| `/wb attach` | подтверждение привязки/повторного включения владельцем |
| `/wb disable` | подтверждение отключения владельцем |
| `/wb check` | фоновая проверка identity; не проверка всех категорий API |
| `/wb sync` | вручную catalog → seller_stocks → wb_stocks → orders |
| `/wb sync catalog` | только карточки |
| `/wb sync seller_stocks` | только склады продавца; требует успешной загрузки карточек |
| `/wb sync wb_stocks` | только склады WB |
| `/wb sync orders` | новые FBS и статусы известных заказов |
| `/wb cards [смещение]` | карточки/варианты/баркоды и связи с нашими товарами |
| `/wb stocks [смещение]` | при смещении 0 обновляет остатки WB и присылает снимок; следующие страницы читают снимок без загрузки; остатки продавца — ранее сохранённые |
| `/wb orders [смещение]` | сохранённые заказы и статусы |
| `/wb map product_id nmID chrtID [barcode]` | явное сопоставление владельцем |
| `/wb help` | справка |

Страница содержит до 10 строк; подсказка следующей страницы включена в ответ.
product_id берётся из локального каталога, nmID/chrtID/баркод — из `/wb cards`.
Нельзя сопоставить чужой product_id, неизвестный вариант или баркод. Повтор той же
команды обновляет связь. Пустой barcode означает весь вариант; он не совмещается
с отдельными связями баркодов этого же варианта. Исчезнувшая при полной загрузке
позиция не удаляет историю связи и помечает её missing.

Успех и давность показываются отдельно для check/catalog/seller_stocks/wb_stocks/orders.
`partial`/`failed` сохраняют прежний снимок и last_success; это не новое полное
обновление. `cancelled` означает прерывание/потерю доступа/отключение или перезапуск.
После перезапуска незаконченная загрузка запускается вручную с начала.
Отсутствие строк без успешной загрузки не означает нулевой остаток.
Импортированные заказы не создают производственные задачи, проводки или отгрузки.

Клиент ограничен чтением. Ответы WB отображаются как данные и не передаются LLM.
Детерминированный `/wb` в Agent разрешает только локальное чтение, без сетевого
инструмента и без сохранения этих команд/ответов в память диалога.

При случайной отправке секрета приложение отклоняет узнаваемый токен/присваивание
WB_API_TOKEN/JWT до обработки форм/памяти; это не удаляет сообщение с серверов
Telegram и не является способом настройки. Секрет задаётся только локально.
