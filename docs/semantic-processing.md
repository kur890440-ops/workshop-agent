# SEMANTIC_MESSAGE_PROCESSING — L0–L3

@PROJECT:WORKSHOP_AGENT
@L3:SEMANTIC_MESSAGE_PROCESSING
@UPDATE
@NO_COMPRESS

## L0 — архитектура

```text
Identity / Active Workshop / Authorization
→ Telegram commands, buttons, active forms
→ local read command OR LLM semantic interpretation
→ existing StructuredCommand + typed reference
→ common validation and deterministic entity resolution
→ authorized Inventory / task service
→ actual SQLite facts in display_unit
```

LLM распознаёт намерение и ссылку, но не задаёт авторизацию, ID материала,
остатки или результат изменения. Бизнес-правила остаются в Inventory.
Для свободной записи LLM создаёт только предложение; выполнение требует кнопки
подтверждения. Числовая форма «Редактировать» сохраняет WA-D029.

## L1 — команды, ссылки и контекст

Расширен существующий `llm.StructuredCommand`: `reference`, `amount`,
`quantity_mode`, `unit`. Новый отдельный набор доменных операций не вводится.
OpenRouterClient реализует `SemanticClient.Interpret` через тот же endpoint,
модель и транспорт. Старый ParseCommand остаётся для существующих сценариев агента.

Поддерживаемый семантический контур:

- Остаток материала: «какой остаток 2», «остаток второго материала»,
  «сколько осталось кисточек?», «а кисточек сколько?».
- Минимальный остаток: «а его минимум?».
- Список материалов, закупки, текущая задача.
- Предложение записи: «установи остаток гипса 10 кг», «добавь 2 кг гипса на склад»,
  «спиши 0,5 кг гипса».

Ссылка бывает `list_position`, `name` или `last`. Числовой ID от модели запрещён.
Название должно быть взято из текущего сообщения. Код сравнивает все подходящие
материалы Workshop, учитывая регистр, ё/е и небольшое расстояние редактирования
слов длиной от четырёх символов. Все совпадения сохраняются; несколько подходящих
материалов приводят к уточнению. Это ограниченная обработка словоформ и опечаток,
а не полный морфологический анализ русского языка.

Контекст использует существующее состояние Telegram UI и Memory Layers:

- Снимок показанных ID в исходном порядке, тип списка, выбранный материал.
- Внутренние User, Workshop, chat/session; таймаут UI-контекста 15 минут неактивности.
- До 100 элементов каталога с ограниченными именами, до 100 ID в LLM-контексте
  и полное количество элементов; код хранит полный снимок нумерации.
- До четырёх последних реплик по 400 символов из short-term.
- Краткое описание активной задачи.

Числа из истории не являются источником истины. Остаток, минимум и рабочая единица
читаются заново после разрешения ссылки. В БД сохраняются базовые количества.

Slash-команды, кнопки и формы обрабатываются раньше семантики. Число в форме
остаётся её значением и не отправляется LLM. Существующий локальный разбор
«сколько второго?» теперь создаёт ту же структурированную команду и использует
общий исполнитель. Сохраняются локальные запросы всех остатков и закупок.

После `/products` предыдущая материальная нумерация не применяется к продуктам:
контекст помечается типом product, и запрос номера материала требует уточнения.
`/setup`, смена Workshop, `/session new`, очистка, истечение срока и перезапуск
сбрасывают релевантность прежних ссылок. Проверяется также идентификатор активной
memory-сессии, включая её закрытие вне Telegram UI.

Явные существующие сценарии MemoryRouter — память, планирование, временные параметры
и подтверждаемые изменения BOM — сохраняются. Маркер `legacy` от семантической
модели не даёт обходить новый валидатор: пользователь получает сообщение об
ограничении и ссылки на команды. Семантика полноценного управления всеми
операциями ERP этим этапом не реализована.

## L2 — решения

Уточнение маршрутизации: явный запрос на сборку обрабатывается до локального
поиска закупок. Слово «заказов» само по себе не является признаком закупки.
Для «соберём 5 заказов» без однозначного продукта бот уточняет продукт и состав
заказа, не создавая задачу с выдуманным составом. В закупки включается только
положительный дефицит: равенство остатка минимуму не даёт строку «заказать 0».

Теперь количество заказов сохраняется в pending_actions до выбора продукта,
уточнения изделий в заказе и подтверждения плана. «Товары» открывает локальный
список с устойчивыми ID. Подробности: [Продукты и контекст сборки](products-assembly.md).

### WA-D041 — единый валидируемый результат

Локальная ссылка и семантический вывод используют общий StructuredCommand.
Для семантического JSON разрешены только action, reference, amount,
quantity_mode, unit. Неизвестные поля, действия, ID, лишние параметры чтения,
неверные комбинации ссылки, отсутствующее количество записи и неконечные числа
отклоняются. Модель не может расширить allowlist своими инструкциями.

### WA-D042 — доверенный контекст ссылки

Номер разрешается по снимку показанного списка, а не текущей сортировке.
Название разрешается внутри Workshop, а не глобально. Последний объект доступен
только в актуальном контексте того же пользователя, чата, мастерской и сессии.
При неоднозначности бот предлагает уточнение. Оценка уверенности не используется
для обхода этих проверок. Ссылка last требует явного местоимения в сообщении.

### WA-D043 — подтверждение свободных изменений

`absolute`, `increase`, `decrease` задают режим предложения. Количество для записи
должно присутствовать цифрами в исходном сообщении; явно указанная единица
проверяется на соответствие тексту и размерности. Если единицы нет, берётся рабочая.
Недопустимо переполнение при переводе в базовую единицу.

Кнопка подтверждения связана с User, chat, Workshop и активной сессией, одноразовая и ограничена
по времени. Повторный запрос изменения заменяет предыдущее предложение; отмена
делает его кнопку недействительной. При подтверждении повторно проверяются
права и рабочая единица. Остаток и движение записываются существующей транзакцией.
Изменение роли или display_unit между запросом и подтверждением блокирует запись.

### WA-D044 — отказ, диагностика и бюджет

Семантический запрос получает до 1024 выходных токенов. При невалидном JSON
разрешена одна дополнительная попытка получения ответа по схеме; расход обеих
попыток суммируется. После ошибки бот предлагает уточнение или `/materials`.
Локальные команды и формы сохраняют работоспособность при отказе модели.

Диагностика пишет маршрут, действие, вид ссылки, источник UI/каталог,
результат валидации/авторизации и usage. Исходный текст сообщения, ключи и
провайдерские ответы в этот журнал не копируются. Семантические ответы чтения
попадают в существующую ограниченную short-term память; нового журнала диалогов нет.

## L3 — реализация, проверка и ограничения

Основные файлы: `internal/llm/semantic.go`, `internal/llm/types.go`,
`internal/telegram/semantic.go`, `internal/telegram/material_reference.go`.

Автоматические проверки охватывают парафразы, словоформы/опечатки, текущий остаток,
неизменность показанной нумерации после добавления материала, минимум последнего
объекта, неоднозначное название, неверный номер, отсутствие списка, переход к
продуктам, сброс сессии и очистку, смену Workshop, приоритет формы, отказ LLM,
неизвестные поля/ID/действия, повтор JSON с учётом usage, запись только после
подтверждения, отмену, отзыв прав, единицы кг, изоляцию пользователей и срок контекста.

Мок-тесты проверяют обработку результата, но не доказывают качество языка.
Для реальной модели добавлена команда `semantic-report`: фиксированные 18 фраз,
синтетический контекст, только Interpret, без открытия рабочей БД и без Telegram.
Модель — настроенная MiniMax/MiniMax-M3. Результаты сохранены:

Счётчик оценивает action, вид/позицию ссылки и параметры изменения на данном наборе;
это не универсальная точность и не end-to-end проверка исполнения каждой фразы.
Суммарный расход четырёх прогонов — 71658 токенов. Неудачные отчёты сохранены.

Произвольные перефразирования могут потребовать уточнения. Сложные словоформы,
количества словами, несколько операций в одном сообщении, длинные каталоги и
операции вне указанного контура не гарантируются. При отсутствии памяти нельзя
восстанавливать номер списка по догадке. Цифровой ввод и явное имя остаются
способом уточнения; меню работает без LLM.

После сборки требуется перезапуск: **Ctrl+C → `.\bin\workshop-agent.exe`**.
После перезапуска снова откройте «материалы», затем спросите «какой остаток 2».
