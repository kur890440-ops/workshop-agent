# PRODUCT_COMPOSITION_MENU

## L0 — архитектура

Telegram → Identity / Active Workshop → Authorization → Products / BOM
→ SQLite: bom_items и Audit Log в одной транзакции.

Товар имеет явно заданный состав на одну единицу. Коробки разных размеров,
пакеты и компоненты выбираются как конкретные складские материалы по ID.
Упаковка не подбирается автоматически. Коробка и пакет, добавленные в состав,
нужны одновременно. Альтернативные варианты упаковки не моделируются.
Меню не вызывает LLM и не изменяет склад или фактическое производство.

## L1 — модель и интерфейс

В карточке товара добавлена кнопка «Состав товара». Пользователь с правами
просмотра открывает карточку через «Просмотреть продукт» в списке товаров;
пользователь с products.write — через «Редактировать продукт».
Карточка чтения не требует products.write. Изменение полей товара по-прежнему
проверяет products.write, изменение состава — bom.write.

Используются существующие setupSession, одноразовые кнопки и bom_items.
В setupSession добавлено состояние composition: снимок строк BOM,
отдельный снимок material IDs, этап, операция, выбранная строка/материал,
значение, рабочая единица и ожидаемая версия состава.
JSON-состав в продукте, памяти или настройках не создаётся.

Этапы: список состава → выбор материала или строки → количество → подтверждение.
При удалении количество не запрашивается. Номера относятся только к снимку
того типа списка, который ожидается на текущем этапе.

Products.Composition читает строки с названиями и единицами, включая вложенные
продукты. ApplyBOMChange добавляет материал, обновляет количество конкретной
строки или удаляет строку. Версия — SHA-256 канонического снимка, упорядоченного
по ID строки. В снимок входят все параметры строк и отображаемые метаданные.

## L2 — решения

- **WA-D055:** состав — существующий BOM на один товар. Новое добавление через
  меню выбирает материал любого складского типа, включая компоненты и упаковку.
  Если позиции нет, её нужно создать через /materials. Свободный текст не
  создаёт материал. Повторное добавление предлагает изменение существующей
  строки; исторические дубли не объединяются автоматически.
- **WA-D056:** количество абсолютное, положительное, конечное; точка и запятая
  поддерживаются. Знаки, ноль, экспоненциальная запись, NaN, бесконечность,
  некорректные числа и переполнение запрещены. Предел введённого количества
  и количества в единице хранения — 1 000 000 000 000.
- **WA-D057:** ввод и показ используют display_unit. Новая строка материала
  хранится в его базовой единице. При изменении существующей строки сохраняется
  её единица: количество пересчитывается из рабочей единицы в единицу строки
  один раз. Например, 0,25 кг становится 250 г в новой строке с unit=g.
  Технологические потери, примечания и тип компонента не меняются. Новая строка
  получает существующее значение потерь по умолчанию 0 и пустое примечание.
  Смена display_unit требует повторного ввода числа, включая смену после
  показа подтверждения. Вложенные продукты показываются и редактируются в шт.
- **WA-D058:** перед записью внутри транзакции проверяются Membership,
  products.read, inventory.read, bom.read, bom.write, активная Workshop,
  принадлежность товара/компонента/строки и версия всего состава. Изменение
  состава вызывает новое подтверждение по свежим данным. Удалённую строку
  нельзя заменить другой под старым номером. Одновременное добавление того же
  материала не создаёт дубль. Изменение и аудит BOM_COMPOSITION_CHANGED атомарны.
- **WA-D059:** изменение состава не создаёт движений, не меняет остатки,
  не закрывает задачу и не удаляет черновик сборки. Потребность в плане читает
  актуальный BOM через существующий расчёт с вложенностью и потерями.
  /setup_stop и «Отмена» возвращают состав без несохранённого изменения;
  «Назад к товару» возвращает карточку; /products выходит из формы.
  Смена Workshop, новая сессия, очистка чата и срок формы 15 минут
  инвалидируют форму и кнопки. При перезапуске несохранённая форма теряется.

## L3 — пример и проверки

```text
товары → Редактировать продукт → номер → Состав товара → Добавить компонент

1. Коробка 185×185×100
2. Коробка 250×200×150
3. Курьер-пакет 250×350

Пользователь: 2
Бот: Коробка 250×200×150. Сколько требуется на один товар? Единица: шт.
Пользователь: 1
Бот: Будет: 1 шт на один товар. [Сохранить] [Отмена]
```

После сохранения снова показывается состав. Далее можно отдельно добавить
курьер-пакет. Для пяти товаров расчёт потребует пять выбранных коробок и
пять пакетов. Пустой/неполный BOM не выдаётся за нулевую потребность.

Тесты composition_test.go в products и telegram используют временные SQLite
и тестовый HTTP-транспорт Telegram:

- Конкретная коробка среди нескольких, коробка и пакет вместе, пустой BOM.
- Добавление, изменение, удаление, дубли, отсутствие записи до подтверждения.
- Неизменившееся значение без аудита, повторные клики, отмена и /setup_stop.
- Количества, ошибки, кг/г, существующие единицы, потери и примечания.
- Смена display_unit до ввода и перед сохранением, конфликт другого изменения.
- Устойчивые material IDs при изменении каталога, чужая строка BOM.
- Просмотр без bom.write, отзыв прав, чужое подтверждение.
- Новая сессия, смена Workshop туда и обратно, очистка чата, срок формы.
- Откат добавления, обновления и удаления при ошибке аудита.
- Сохранность материалов, движений, производственных записей, задачи и черновика.
- Расчёт реальной потребности по сохранённому BOM, вложенные продукты.
- Длинные списки с сохранением снимка ID и отсутствие LLM-вызовов.

Ограничения: новое добавление вложенного продукта через это меню не реализовано;
существующие вложенные строки доступны для просмотра, изменения количества
и удаления. Выбор альтернатив упаковки и редактирование потерь/примечаний
в меню не добавлены. Права чтения каталога материалов нужны для показа состава.

Миграция схемы не требуется. Проверка: go test ./...
Сборка: go build -o bin/workshop-agent.exe ./cmd/workshop-agent

Нужен перезапуск бота: **Ctrl+C → .\bin\workshop-agent.exe**.
