## L0 — место в архитектуре

Меню материалов — детерминированный сценарий существующего Telegram Interface.
После определения внутреннего User и активной Workshop проверяются Membership
и Permissions. Команды меню вызывают Inventory напрямую, без LLM Command Interpreter.

```text
Telegram User
→ Identity (internal user_id)
→ Active Workshop Context (workshop_id)
→ Membership / Permissions / Authorization
→ Telegram Interface: /materials
→ Inventory
→ Deterministic Business Logic
→ SQLite: materials + inventory_movements
```

SQLite остаётся источником истины для остатков. Memory Layers не используются
для хранения остатков или принятия решений в этом меню.

## L1 — сущности и сценарии

Используются существующие User, Workshop, WorkshopMembership, Role, Permission,
UserWorkshopContext, Material и InventoryMovement. Новые бизнес-сущности не вводятся.

Состояние ввода хранится в Telegram-адаптере по `(chat_id, user_id)` и содержит
`workshop_id`, этап, снимок списка `material_id` и выбранный `material_id`.
Это временное состояние формы; после перезапуска процесса незавершённый ввод теряется.

### Просмотр

После показа меню можно спросить «сколько второго?», «сколько 2?» или
«сколько первого материала осталось?». Обработчик без LLM использует снимок
ID последнего показанного списка, связанный с пользователем, чатом и Workshop.
Остаток и рабочая единица читаются из БД заново. Снимок действует 15 минут;
после перезапуска, очистки чата, нового диалога или смены Workshop нужно открыть
список заново. При отсутствии контекста или неверном номере бот просит уточнение.

Слова «материалы» и «остатки» без слеша также открывают меню, без учёта регистра
и без вызова LLM. Эти текстовые варианты действуют вне незавершённой формы,
чтобы её значения не принимались за команды. `/materials` открывает меню
и сбрасывает форму явно.

`/materials` показывает материалы активной Workshop с нумерацией от 1,
названием, текущим остатком и единицей измерения. Единицы в интерфейсе:
г, кг, мл, л, шт; отображается рабочая единица материала display_unit (см. [MATERIAL_DISPLAY_UNITS](material-display-units.md)).
В существующем Inventory килограммы нормализуются в граммы, литры — в миллилитры.

Под списком пользователь с `inventory.write` видит «Добавить» и, если список
не пуст, «Редактировать» и «Единица измерения». При пустом списке показаны «Пока нет материалов.»
и кнопка «Добавить». VIEWER получает только просмотр.

### Добавление

«Добавить» → название → категория → единица измерения → текущий остаток
→ минимальный остаток → проверка введённых данных → «да» для сохранения
или «нет» для отмены. Используется существующий сценарий `/setup_add_material`.

Название ограничено 200 символами. Начальный и минимальный остатки могут быть
нулевыми; отрицательные и нечисловые значения запрещены. Дробные числа принимаются
с точкой или запятой. Проверяется переполнение при переводе в базовые единицы.

### Изменение остатка

«Редактировать» → номер из показанного списка → название, актуальный остаток
и единица → «Введите новый остаток или изменение» → ввод числа → сохранение
→ сообщение с изменением и новым остатком → обновлённое меню.

Примеры: `+5`, `5`, `-2`, `-2,5`, `+2.5`.
Число без начального знака устанавливает абсолютный остаток; начальный `+` или `-`
означает относительное изменение. Пробелы по краям удаляются до определения режима.
Например, при остатке 50 ввод `10000` устанавливает 10000, `+10000` даёт 10050,
`-20` даёт 30, а `0` обнуляет остаток.
Другие свойства материала этим сценарием не редактируются.

`/setup_stop` отменяет незавершённый ввод без записи данных.
Повторный `/materials` открывает список заново и сбрасывает текущую форму.

## L2 — принятые решения

### WA-D027 — детерминированное меню

Просмотр, добавление и изменение через меню работают без вызова LLM.
Telegram-адаптер использует существующие Inventory и механизм авторизации.

### WA-D028 — номер связан с ID

Номер относится к снимку списка, показанному пользователю. Он преобразуется
в устойчивый `material_id`, а не в позицию заново отсортированного списка.
Добавление другого материала между показом списка и вводом номера не меняет выбор.

### WA-D029 — абсолютный остаток или относительное изменение

Обновлено: прежнее правило «любое число является delta» заменено.
Без начального знака число задаёт новый абсолютный остаток в отображаемой рабочей
единице; с начальным `+` или `-` число является delta.
Актуальный остаток читается в SQLite внутри транзакции. При абсолютной установке
delta для движения вычисляется как новый остаток минус актуальный, а не показанный
ранее в меню. Ввод корректного числа завершает действие без дополнительного подтверждения.
Если абсолютный остаток уже равен введённому, движение не создаётся, бот сообщает
«Остаток уже равен указанному значению» и возвращает меню.
При установке бот показывает новый и предыдущий остатки; при относительном изменении
показывает delta и новый остаток.
Добавление нового материала сохраняет явное подтверждение «да».

### WA-D030 — атомарность и авторство

Изменение остатка и вставка InventoryMovement выполняются одной транзакцией.
При ошибке записи движения изменение остатка откатывается.
Движение сохраняет `workshop_id`, `material_id`, delta и внутренний `user_id` автора.

### WA-D031 — права и изоляция

Для списка требуется `inventory.read`, для добавления и изменения — `inventory.write`.
Права проверяются при открытии действия, на шагах ввода и при записи через сервис.
VIEWER не получает кнопок изменения. Отзыв доступа или права записи блокирует
незавершённую операцию. Запросы ограничены `workshop_id` и `material_id`.

Кнопки связаны с пользователем и чатом, имеют срок действия и одноразовое выполнение
через существующий механизм UI. Кнопка другой Workshop отклоняется, если эта Workshop
не является текущей. Смена Workshop через UI сбрасывает форму; несовпадение контекста
при следующем вводе также сбрасывает её.

### WA-D032 — числовая валидация

Абсолютный остаток — конечное неотрицательное число; беззнаковый `0` разрешён.
Относительное изменение — конечное ненулевое число; `+0` и `-0` отклоняются.
Неверные номера, нечисловые значения,
NaN, бесконечность, переполнение и результат ниже нуля запрещены.
Некорректный ввод не изменяет склад и позволяет повторить ввод либо отменить форму.

### WA-D033 — ограничения Telegram

Длинный список разделяется на сообщения с сохранением общей нумерации.
Кнопки следуют за последней частью. Лимит разделения — 3500 единиц UTF-16,
с учётом символов вне BMP и одного очень длинного исторического названия.
В запросе изменения длинное название сокращается только для отображения;
полное имя в базе и привязка к `material_id` сохраняются.

## L3 — выполненная задача и проверки

@L3:MATERIALS_MENU

Реализовано:

- Пронумерованный список материалов активной Workshop.
- Кнопки «Добавить» и «Редактировать» с учётом прав.
- Использование существующей формы создания материала.
- Выбор материала по номеру, абсолютная установка или относительное изменение остатка.
- Отмена без сохранения и возврат к меню после успешной записи.
- Проверки прав, контекста мастерской, чисел и неотрицательного остатка.
- Атомарная запись остатка и складского движения с автором.
- Обработка пустого и длинного списка.

Основные файлы:

- [Telegram menu](../internal/telegram/materials.go).
- [Telegram forms](../internal/telegram/bot.go).
- [Callbacks and authorization](../internal/telegram/identity.go).
- [Atomic inventory adjustment](../internal/inventory/adjustment.go).
- [Scenario tests](../internal/telegram/materials_test.go).

Автоматические проверки покрывают добавление, увеличение и уменьшение остатка,
точку и запятую, невалидный ввод, отмену создания и изменения, неизменность выбора
после добавления нового элемента списка, автора движения, смену Workshop,
старое меню другой Workshop, отзыв права записи, VIEWER, отключённого участника,
чужой `material_id`, пустой список, длинное Unicode-название и откат при ошибке
вставки InventoryMovement. Сценарии меню также проверены с отключённым Agent.

Обновление WA-D029 дополнительно проверено на абсолютной установке, обнулении,
отсутствии нулевого движения при неизменившемся остатке, относительных изменениях,
дробных числах, актуальности delta после стороннего изменения остатка и откате
абсолютной установки при ошибке вставки движения.
